# העלאה לאוויר — מדריך מלא

המטרה: שני קישורים חיים שאפשר לשלוח למישהו, ודמו שנפתח מלא בנתונים
במקום מסך ריק.

בסוף התהליך יהיו לך:

| מה | כתובת לדוגמה |
|---|---|
| דשבורד בעל העסק | `https://maslul-dashboard.vercel.app` |
| אפליקציית השליח | `https://maslul-courier.vercel.app` |

הכל בשכבות החינמיות. אין צורך בכרטיס אשראי.

> **הערה על סדר:** חלקים א׳–ג׳ מעלים את הקוד לאוויר. חלק ד׳ ממלא אותו
> בנתונים. אין טעם לעשות את ד׳ לפני שא׳–ג׳ עובדים.

---

## חלק א׳ — העלאת הקוד ל-GitHub

הריפו קיים אצלך במחשב אבל אינו מחובר לשום מקום ברשת. Vercel בונה מתוך
GitHub, ולכן זה הצעד הראשון. הריפו עצמו הוא גם חלק מתיק העבודות.

**1.** פתח את https://github.com/new

**2.** ב-`Repository name` כתוב: `maslul`

**3.** בחר **Public**.

**4.** אל תסמן שום תיבה בקטע "Initialize this repository" — לא README,
לא .gitignore, לא רישיון. יש לנו כבר.

**5.** לחץ `Create repository`.

**מה אתה אמור לראות:** דף עם הכותרת "Quick setup" והוראות. אל תעתיק
משם — השתמש בפקודות שלמטה, הן מותאמות למצב שלך.

**6.** העתק את שתי השורות האלה והרץ אותן בטרמינל שבתוך תיקיית הפרויקט.
החלף `USERNAME` בשם המשתמש שלך ב-GitHub:

```bash
git remote add origin https://github.com/USERNAME/maslul.git
```

**7.** ואז:

```bash
git push -u origin main
```

**מה אתה אמור לראות:** שורות התקדמות, ובסוף `branch 'main' set up to
track 'origin/main'`. רענן את דף ה-GitHub — הקבצים אמורים להופיע.

> אם הוא מבקש שם משתמש וסיסמה ונכשל: GitHub לא מקבל סיסמה רגילה
> מהטרמינל. הדרך הפשוטה היא להתקין את https://cli.github.com ולהריץ
> `gh auth login` פעם אחת.

## חלק ב׳ — פריסת הדשבורד ב-Vercel

**8.** פתח את https://vercel.com/signup והירשם **עם חשבון GitHub**
(כפתור "Continue with GitHub"). כך Vercel רואה את הריפו מיד.

**9.** פתח את https://vercel.com/new

**10.** מצא את `maslul` ברשימה ולחץ `Import`.

**11.** עכשיו החלק החשוב. חפש את השדה **Root Directory** ולחץ `Edit`.

**12.** בחר את התיקייה `apps/dashboard` ולחץ `Continue`.

**מה אתה אמור לראות:** ליד Root Directory כתוב `apps/dashboard`, ותחת
Framework Preset כתוב `Vite`. אם כתוב שם `Other` — עצור ובדוק שבחרת
את התיקייה הנכונה.

**13.** פתח את הקטע `Environment Variables` והוסף שני משתנים:

| Name | Value |
|---|---|
| `VITE_SUPABASE_URL` | הכתובת מהפרויקט שלך ב-Supabase |
| `VITE_SUPABASE_ANON_KEY` | מפתח ה-`anon` **public** |

את שני הערכים תמצא כאן: https://supabase.com/dashboard/project/_/settings/api
— תחת `Project URL` ותחת `Project API keys` → `anon` `public`.

> **חשוב:** רק המפתח שכתוב לידו `anon`. המפתח `service_role` **לעולם
> לא** נכנס לכאן ולא לשום מקום בקוד הלקוח — הוא עוקף את כל הרשאות
> ה-RLS. אם הודלף בטעות, החלף אותו מיד באותו מסך.
>
> מפתח ה-`anon` **כן** אמור להיות פומבי. הוא נמצא ממילא בקוד שכל
> מבקר מוריד. מה שמגן על הנתונים זה RLS, לא הסתרת המפתח.

**14.** לחץ `Deploy` וחכה. זה לוקח דקה עד שתיים.

**מה אתה אמור לראות:** מסך חגיגי עם צילום מסך של האתר וכפתור `Continue
to Dashboard`. לחץ על הקישור ותראה את מסך ההתחברות בעברית.

## חלק ג׳ — פריסת אפליקציית השליח

אותו דבר, פרויקט **שני** מאותו ריפו.

**15.** פתח שוב את https://vercel.com/new

**16.** מצא את `maslul` ולחץ `Import` שוב.

**17.** ב-`Project Name` שנה ל-`maslul-courier` (אחרת Vercel יתלונן
שהשם תפוס).

**18.** ב-**Root Directory** בחר הפעם את `apps/courier`.

**19.** הוסף את **אותם שני משתני הסביבה** מצעד 13. כן, שוב — כל פרויקט
ב-Vercel נבנה בנפרד ולא מכיר את המשתנים של השני.

**20.** לחץ `Deploy`.

**מה אתה אמור לראות:** מסך התחברות, הפעם בעיצוב הצר של הנייד.

> **מלכודת שכדאי להכיר:** משתני `VITE_` נצרבים לתוך הקוד **בזמן
> הבנייה**, לא נקראים בזמן ריצה. אם תשנה מפתח ב-Vercel, זה לא ישפיע
> על האתר עד שתריץ `Redeploy`. אם משהו לא עובד אחרי שינוי משתנה —
> זו כמעט תמיד הסיבה.

## חלק ד׳ — מילוי הדמו בנתונים

עכשיו יש שני אתרים חיים ושניהם ריקים. מבקר שנוחת על מסך ריק לא מבין
מה בנית. הצעדים הבאים יוצרים חשבון דמו מלא.

**21.** פתח את הדשבורד החי שלך, לחץ על "הרשמה" וצור חשבון **עסק**:

- אימייל: `demo@maslul.local`
- סיסמה: בחר סיסמה וזכור אותה — היא תופיע ב-README כדי שמבקרים יוכלו
  להיכנס. אל תשתמש בסיסמה שאתה משתמש בה במקום אחר.
- שאר השדות: מלא כל דבר. הסקריפט ידרוס אותם.

**22.** פתח את אפליקציית השליח החיה וצור חשבון **שליח**:

- אימייל: `courier@maslul.local`
- סיסמה: אותה סיסמה, כדי שיהיה קל להציג.

> אם ההרשמה נכשלת עם שגיאה על אימות אימייל, כבה את האישור כאן:
> https://supabase.com/dashboard/project/_/auth/providers
> → `Email` → כבה את `Confirm email` → `Save`.

**23.** בטרמינל, בתיקיית הפרויקט, הרץ:

```bash
npm run seed
```

**מה אתה אמור לראות:** רשימה של שתים-עשרה כתובות אמיתיות בבאר שבע עם
המרחק שלהן מהמסעדה, ושורה שאומרת שנכתב הקובץ
`supabase/seed/demo_seed.sql`.

**24.** פתח את הקובץ `supabase/seed/demo_seed.sql` ובדוק ששני
האימיילים בראשו תואמים למה שנרשמת בפועל בצעדים 21–22.

**25.** העתק את **כל תוכן הקובץ**, הדבק כאן, ולחץ `Run`:
https://supabase.com/dashboard/project/_/sql/new

**מה אתה אמור לראות:** `Success. No rows returned`. אם מופיעה שגיאה
בעברית שאומרת "לא נמצא משתמש עם האימייל" — האימייל בקובץ אינו זהה
לאימייל שנרשמת איתו. תקן וחזור על הצעד.

**26.** רענן את הדשבורד החי.

## מה אתה אמור לראות בסוף

בדשבורד:

- שם העסק **פלאפל הנגב (דמו)** בראש המסך
- בלשונית **משלוחים** — שתים-עשרה משלוחים בסטטוסים שונים
- על לשונית **מפה** — המספר `(1)`. זה המשלוח היחיד בלי קואורדינטות,
  וכך המערכת מונעת ממנו להיעלם. לחיצה עליו מאפשרת נעיצה ידנית
- על לשונית **מסלולים** — המספר `(1)`, מסלול פעיל עם ארבע עצירות
- בלשונית **שליחים** — "אבי (שליח דמו)" במשמרת פעילה

באפליקציית השליח, אחרי התחברות עם `courier@maslul.local`:

- המסלול הפעיל עם ארבע העצירות **בסדר שנקבע**
- שתי עצירות מסומנות כנמסרו, שתיים ממתינות

**הרצה חוזרת של הסקריפט מאפסת את הדמו.** אם מבקר סימן "נמסר" על הכל
וזה נראה עלוב — הרץ שוב את צעד 25 והכל חוזר למצב ההתחלתי.

## תחזוקה שוטפת

**כל `git push` ל-`main` מפעיל פריסה אוטומטית** בשני הפרויקטים. אין
צורך לעשות שום דבר ידני אחרי הפעם הראשונה.

**הנתונים בדמו מזדקנים.** כל חותמות הזמן מחושבות יחסית לרגע ההרצה
("לפני 12 דקות"), ולכן אחרי שבוע הדמו יראה משלוחים שממתינים שבוע.
הרץ את צעד 25 מחדש לפני שאתה שולח את הקישור למישהו.
