המטרה: קישור חי אחד שאפשר לשלוח למישהו, ודמו שנפתח מלא בנתונים
במקום מסך ריק.

בסוף התהליך יהיו לך:

| מה | כתובת לדוגמה |
|---|---|
| האתר — מסך פתיחה עם כניסה לבעלי עסקים ולשליחים | `https://maslul-dashboard.vercel.app` |
| קישור ישיר להתחברות השליח | `https://maslul-dashboard.vercel.app/courier` |

הכל בשכבות החינמיות. אין צורך בכרטיס אשראי.

> **הערה על סדר:** חלקים א׳–ב׳ מעלים את הקוד לאוויר. חלק ג׳ נחוץ רק
> אם כבר פרסת בעבר את הגרסה הישנה, עם שני אתרים. חלק ד׳ ממלא את האתר
> בנתונים — אין טעם לעשות אותו לפני שהאתר עובד.

## חלק א׳ — העלאת הקוד ל-GitHub

הריפו קיים אצלך במחשב אבל אינו מחובר לשום מקום ברשת. Vercel בונה מתוך
GitHub, ולכן זה הצעד הראשון. הריפו עצמו הוא גם חלק מתיק העבודות.

**1.** פתח את https://github.com/new

**2.** ב-`Repository name` כתוב: `maslul`

**3.** בחר **Public**.

**4.** אל תסמן שום תיבה בקטע "Initialize this repository" — לא README,
לא .gitignore, לא רישיון. יש לנו כבר.

**5.** לחץ `Create repository`.

**מה אתה אמור לראות:** דף עם הכותרת "Quick setup" והוראות. אל תעתיק
משם — השתמש בפקודות שלמטה, הן מותאמות למצב שלך.

**6.** הרץ את השורה הבאה בטרמינל, בתוך תיקיית הפרויקט
(`C:\Users\galya\OneDrive\Desktop\delivery_optemizer`):

```bash
git remote add origin https://github.com/GalYakounin/maslul.git
```

**7.** ודא שהכתובת נכנסה נכון:

```bash
git remote -v
```

**מה אתה אמור לראות:** שתי שורות, ובשתיהן `GalYakounin`. אם רשום שם
משהו אחר, תקן כך:

```bash
git remote set-url origin https://github.com/GalYakounin/maslul.git
```

**8.** עכשיו דחוף:

```bash
git push -u origin main
```

**מה אתה אמור לראות:** שורות התקדמות, ובסוף `branch 'main' set up to
track 'origin/main'`. רענן את דף ה-GitHub — הקבצים אמורים להופיע.

> **אימות מול GitHub.** git יפתח לך דפדפן. אם האימות דרך אפליקציית
> GitHub Mobile נתקע או מציג `Verification request timed out` — לחץ
> על `Send a code via email` בתחתית אותו מסך, ותקבל קוד למייל במקום.
>
> אם git מבקש שם משתמש וסיסמה רגילים ונכשל: GitHub לא מקבל סיסמה
> מהטרמינל. התקן את https://cli.github.com והרץ `gh auth login` פעם אחת.

## חלק ב׳ — פריסת האתר ב-Vercel

**9.** פתח את https://vercel.com/signup והירשם **עם חשבון GitHub**
(כפתור "Continue with GitHub"). כך Vercel רואה את הריפו מיד.

**10.** פתח את https://vercel.com/new

**11.** מצא את `maslul` ברשימה ולחץ `Import`.

**12.** עכשיו החלק החשוב. חפש את השדה **Root Directory** ולחץ `Edit`.

**13.** בחר את התיקייה `apps/web` ולחץ `Continue`.

**מה אתה אמור לראות:** ליד Root Directory כתוב `apps/web`, ותחת
Framework Preset כתוב `Vite`. אם כתוב שם `Other` — עצור ובדוק שבחרת
את התיקייה הנכונה.

**14.** פתח את הקטע `Environment Variables` והוסף שני משתנים:

| Name | Value |
|---|---|
| `VITE_SUPABASE_URL` | הכתובת מהפרויקט שלך ב-Supabase |
| `VITE_SUPABASE_ANON_KEY` | מפתח ה-`anon` **public** |

את שני הערכים תמצא כאן: https://supabase.com/dashboard/project/_/settings/api
— תחת `Project URL` ותחת `Project API keys` → `anon` `public`.

> **חשוב:** רק המפתח שכתוב לידו `anon`. המפתח `service_role` **לעולם
> לא** נכנס לכאן ולא לשום מקום בקוד הלקוח — הוא עוקף את כל הרשאות
> ה-RLS. אם הודלף בטעות, החלף אותו מיד באותו מסך.
>
> מפתח ה-`anon` **כן** אמור להיות פומבי. הוא נמצא ממילא בקוד שכל
> מבקר מוריד. מה שמגן על הנתונים זה RLS, לא הסתרת המפתח.

**15.** לחץ `Deploy` וחכה. זה לוקח דקה עד שתיים.

**מה אתה אמור לראות:** מסך חגיגי עם צילום מסך של האתר וכפתור `Continue
to Dashboard`. לחץ על הקישור ותראה מסך פתיחה בעברית עם שתי אפשרויות:
"כניסה לבעלי עסקים" ו"כניסה לשליחים".

## חלק ג׳ — מעבר מהפריסה הישנה (רק אם כבר פרסת שני אתרים)

עד 10/2026 הדשבורד והשליח היו שני אתרים, כל אחד פרויקט משלו ב-Vercel.
**אם זו הפריסה הראשונה שלך — דלג לחלק ד׳.**

אחרי האיחוד התיקיות `apps/dashboard` ו-`apps/courier` כבר לא קיימות,
ושני הפרויקטים הישנים ייכשלו בבנייה עד שתפנה אותם לתיקייה החדשה.
**בנייה שנכשלה לא מורידה את האתר** — Vercel ממשיך להציג את הגרסה
האחרונה שעבדה. אז אין לחץ, אבל גם אין עדכון עד שתעשה את זה.

**16.** פתח את https://vercel.com/dashboard ולחץ על הפרויקט `maslul-dashboard`.

**17.** לחץ `Settings` למעלה, ואז `Build and Deployment` בתפריט הצד.
מצא את **Root Directory**, שנה ל-`apps/web` ולחץ `Save`.

> אם אינך מוצא את `Build and Deployment` — חפש את המילים Root Directory
> בעמוד ההגדרות. Vercel מזיז את הסעיף הזה מדי פעם.

**18.** עבור ללשונית `Deployments`. ליד הפריסה העליונה לחץ על שלוש
הנקודות ← `Redeploy` ← `Redeploy`.

**מה אתה אמור לראות:** אחרי דקה עד שתיים, סטטוס `Ready` ירוק. פתח את
האתר — מסך פתיחה עם שתי אפשרויות.

**19.** עכשיו הפרויקט `maslul-courier`. שתי דרכים, ושתיהן תקינות:

- **אם שלחת פעם את הקישור שלו למישהו**, או שהוא מופיע בקורות החיים:
  חזור על צעדים 17–18 גם בו, עם אותו `apps/web`. הקישור הישן ימשיך
  לעבוד ויפתח את אותו אתר.
- **אחרת — מחק אותו:** `Settings` ← גלול לתחתית ← `Delete Project`.

**20.** במחשב שלך: קובץ ה-`.env` לא עובר עם git (בכוונה), ולכן נשאר
בתיקייה הישנה. העתק את `apps/dashboard/.env` אל `apps/web/.env`. אחרי
זה אפשר למחוק את התיקיות `apps/dashboard` ו-`apps/courier` — נשאר בהן
רק ה-`.env` הישן.

**21.** בדוק את הקישור הישיר: פתח את כתובת האתר עם `/courier` בסוף.

**מה אתה אמור לראות:** ישר "התחברות לשליחים", בלי מסך הפתיחה.

> **מלכודת שכדאי להכיר:** משתני `VITE_` נצרבים לתוך הקוד **בזמן
> הבנייה**, לא נקראים בזמן ריצה. אם תשנה מפתח ב-Vercel, זה לא ישפיע
> על האתר עד שתריץ `Redeploy`. אם משהו לא עובד אחרי שינוי משתנה —
> זו כמעט תמיד הסיבה.

## מה אתה אמור לראות בסוף

בכניסה לבעלי עסקים, עם `demo@maslul.local`:

- שם העסק **פלאפל הנגב (דמו)** בראש המסך
- בלשונית **משלוחים** — שתים-עשרה משלוחים בסטטוסים שונים
- על לשונית **מפה** — המספר `(1)`. זה המשלוח היחיד בלי קואורדינטות,
  וכך המערכת מונעת ממנו להיעלם. לחיצה עליו מאפשרת נעיצה ידנית
- על לשונית **מסלולים** — המספר `(2)`: מסלול פעיל עם ארבע עצירות,
  ו**מסלול טיוטה** עם שלוש. בטיוטה יש את הכפתור "חשב סדר אופטימלי" —
  זה הפיצ׳ר המרכזי של הפרויקט, והוא מופיע רק בטיוטות
- בלשונית **שליחים** — "אבי (שליח דמו)" במשמרת פעילה

בכניסה לשליחים, עם `courier@maslul.local` — בחלון גלישה בסתר או
בטלפון, כי דפדפן אחד מחזיק חשבון אחד:

- המסלול הפעיל עם ארבע העצירות **בסדר שנקבע**
- שתי עצירות מסומנות כנמסרו, שתיים ממתינות

**הרצה חוזרת של הסקריפט מאפסת את הדמו.** אם מבקר סימן "נמסר" על הכל
וזה נראה עלוב — הרץ שוב את צעד 26 והכל חוזר למצב ההתחלתי.

## חלק ו׳ — הפעלת חישוב המסלול (שלב 6)

הכפתור "חשב סדר אופטימלי" צריך זמני נסיעה אמיתיים. הם מגיעים מ-
OpenRouteService, ומפתח ה-API שלו **אסור שיגיע לקוד הלקוח** — בשונה
ממפתח ה-`anon` של Supabase, אין כאן RLS שמגן עליו, ומי שישיג אותו
ישרוף את המכסה. לכן הוא יושב ב-Edge Function.

**בלי החלק הזה המערכת עדיין עובדת.** הכפתור ייפול חזרה להערכה ממרחק
אווירי, יסמן זאת למשתמש, והסידור הידני בחיצים ממשיך כרגיל.

**32.** פתח את https://openrouteservice.org/dev/#/signup והירשם. חינם,
בלי כרטיס אשראי.

**33.** אחרי האישור במייל, היכנס ל-Dashboard שם וצור `Request a token`
מסוג **Standard**. העתק את המפתח.

**מה אתה אמור לראות:** מחרוזת ארוכה. שמור אותה בצד — **היא סוד אמיתי**,
לא כמו מפתח ה-`anon`.

באותו מסך יש טבלת `Remaining Key Quotas`. השורה הרלוונטית היא
**Matrix V2: 500 ליום, 40 לדקה**. הצריכה של מסעדה אחת היא כ-25 ביום,
אז יש מרווח נוח — אבל אל תריץ מדידות המוניות על המפתח הזה בלי לחשב.

**34.** בטרמינל, בתיקיית הפרויקט, התחבר ל-Supabase:

```bash
npx supabase login
```

ייפתח דפדפן לאישור. אין צורך להתקין כלום — `npx` מוריד לשימוש חד-פעמי.

**35.** קשר את התיקייה לפרויקט:

```bash
npx supabase link --project-ref npbmrwmshgoqxfcotzfh
```

הוא יבקש את סיסמת מסד הנתונים. אם אינך זוכר אותה, אפשר לאפס כאן:
https://supabase.com/dashboard/project/npbmrwmshgoqxfcotzfh/settings/database

**36.** מסור את המפתח לפונקציה. החלף `<המפתח>` במה שהעתקת בצעד 33:

```bash
npx supabase secrets set ORS_API_KEY=<המפתח>
```

**37.** פרוס את הפונקציה:

```bash
npx supabase functions deploy duration-matrix
```

**מה אתה אמור לראות:** `Deployed Function duration-matrix`.

**38.** בדוק באפליקציה: בדשבורד, לשונית **מסלולים**, סמן שני משלוחים
או יותר, בחר שליח, וצור מסלול. בכרטיס שנוצר (במצב `טיוטה`) יופיע
הכפתור **"חשב סדר אופטימלי"**.

**מה אתה אמור לראות:** העצירות מסתדרות מחדש, ומתחתן שורה עם החיסכון
המשוער בדקות. אם כתוב שם גם *"החישוב התבסס על מרחק אווירי מוערך"* —
הפונקציה לא ענתה, וההודעה לידה תגיד למה.

> **הכפתור מופיע רק בטיוטה.** מסלול ששוגר קופא — זה נובע מהאילוץ
> העסקי, לא ממגבלה טכנית. אצווה שיצאה היא סגורה.

## תחזוקה שוטפת

**כל `git push` ל-`main` מפעיל פריסה אוטומטית.** אין צורך לעשות שום
דבר ידני אחרי הפעם הראשונה.

**Edge Functions אינן נפרסות עם git push.** שינוי ב-
`supabase/functions/` דורש `npx supabase functions deploy` מחדש.

**הנתונים בדמו מזדקנים.** כל חותמות הזמן מחושבות יחסית לרגע ההרצה
("לפני 12 דקות"), ולכן אחרי שבוע הדמו יראה משלוחים שממתינים שבוע.
הרץ את צעד 26 מחדש לפני שאתה שולח את הקישור למישהו.

---

## אם משהו לא עובד

| מה קורה | כמעט תמיד הסיבה |
|---|---|
| האתר עולה אבל ההתחברות נכשלת | משתני הסביבה חסרים או שגויים בפרויקט הזה ב-Vercel. בדוק ואז `Redeploy` |
| שינית משתנה ושום דבר לא השתנה | `VITE_` נצרב בזמן בנייה. חייב `Redeploy` |
| הבנייה נכשלת ב-Vercel | הרץ `npm run build` אצלך במחשב. אותה שגיאה תופיע, עם יותר פרטים |
| התחברתי כשליח, והעסק בטאב השני התנתק | דפדפן אחד מחזיק חשבון אחד. פתח את הצד השני בחלון גלישה בסתר או בטלפון |
| הבנייה נכשלת ומזכירה `apps/dashboard` או `apps/courier` | Root Directory עדיין מצביע לתיקייה הישנה. ראה חלק ג׳ |
| חיפוש כתובת לא מוצא כלום | נטענה **באר שבע בלבד**. מחוץ לה יש רק גיבוי Photon, שחלש בפריפריה |
